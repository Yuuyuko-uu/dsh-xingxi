# 星汐 · dsh-xingxi

把整理好的记忆档案连成一张**看得见的星图**。

记忆卡的一条是一颗星，日记的一天也是一颗星。点一颗星看见它背后的原话；
需要深挖的时候，让 AI 用 `xingxi_read` 去档案里把那一小段原文捞出来。

> 本文对应 **0.3.2**。更早的版本界面和功能可能对不上，建议先升级。

---

## 它解决什么

上下文一压缩，AI 就不知道自己是谁了。主流的解法是「存更多、检索更准」——
但存得好和**想得起来**是两件事。

星汐做两件事：

1. **看得见**：把「我是谁」「我们怎么走到今天」摊成一张图，你能看见结构、能顺着线走。
2. **查得到**：给 AI 一个检索工具，想不起哪件事时去档案里翻原文，而不是猜。

> 它不替代任何记忆插件。遗忘、权重、每轮注入是别的插件的事；
> 星汐负责**把已经整理好的档案摊开**，以及**帮你把历史对话整理成档案**（拾星）。

## 长什么样

一片深色星空，每颗星是一颗柔光圆珠：

- 中间最亮那颗 = 记忆卡第一章第一条
- 八章的星各自成群；同一章的星连最近的几颗，连成淡淡的星座底纹
- 提到同一个少见的词的两颗星，另有一根橙色弱连
- **越新的星越亮**（按内容里的日期算），老星只是变暗，不会消失
- 鼠标停在一颗星上：它和跟它相连的星保持亮度，其余压暗，连着的线亮起来
- 点一颗星看原文；搜索框按关键词把不命中的压暗
- 顶部：节点数 / 日记数 / 图例；右上：拖拽旋转、滚轮缩放、连线开关、重置

面板有四个页签：

| 页签 | 是什么 | 能做什么 |
|---|---|---|
| **星图** | 上面那张星空 | 悬停、点击看原文、搜索、拖拽旋转、滚轮缩放、连线开关、重置 |
| **星册** | 记忆卡条目列表 | 搜索；点一条看原文 |
| **星历** | 日记时间线 | 搜索；点一天看原文 |
| **星坊** | 当前会话的设置 | 绑文件夹、拾星 / 补星 / 停止、选模型、看备份 / 恢复、定时整理 |

右侧是会话栏：只列当前工作区、没归档、已经有档案的会话；长按拖动可以排序。

**看图、查档案都是只读的**；只有你点「拾星 / 补星 / 定时」时，它才会往绑定的文件夹里写整理结果。

## 装上

### 环境要求

| 需要 | 版本 / 说明 |
|---|---|
| Node.js | **>= 22**（`package.json` 的 `engines`） |
| DeepSeek Harness | **>= 0.2.1-rc.2**；版本太低可能装不上，或侧栏不出现面板 |
| 界面 | DSH Web 侧栏面板（桌面版就是 Web UI） |

### 安装

```bash
dsh plugin add dsh-xingxi
```

或者从仓库装最新代码：

```bash
dsh plugin add github:Yuuyuko-uu/dsh-xingxi
```

如果 CLI 提示要指定 profile，在命令里加上 `--profile <名字>`（Web 一般是 `web`），
具体写法以 `dsh plugin --help` 为准。

装完**重开 DSH**，侧栏会多一个「星汐」面板。

### 升级

再执行一次安装命令即可，装到的就是最新版；
用 GitHub 源装的就重新执行一次 `dsh plugin add github:Yuuyuko-uu/dsh-xingxi`。
升完重开 DSH。

### 卸载

用 `dsh plugin remove dsh-xingxi`（或在插件管理里移除）卸载，重开 DSH。

**卸载不会删档案**：记忆卡和日记还在你绑的文件夹里。
插件自己的配置、日志和默认档案在 `~/.dsh/xingxi/`，要清就手动删；删了就找不回设置和默认档案。

### 数据放在哪

- `~/.dsh/xingxi/config.json` —— 配置
- `~/.dsh/xingxi/pick.log` —— 运行日志（出问题先看这个）
- `~/.dsh/xingxi/会话/<会话id>/` —— 没绑文件夹的会话，档案默认在这里

Windows 的 `~` 是 `C:\Users\<你的用户名>`；设了 `DSH_HOME` 就以它为准。

## 三步上手

### 第一步：给它一个文件夹

星汐按**会话**管理档案：每个会话绑一个文件夹，星图、星册、星历画的都是那个文件夹里的东西。

打开星汐 → 底部「星坊」→「现在这个会话」→ 点 **选…**，选一个文件夹（比如 `D:\档案\某某`；
第一次用建议选空文件夹，里面已有的 `记忆卡.md` / `日记\` 会被直接认出来）。

> **想给所有会话共用一份「本机档案」？** 目前没有设置界面，要手改 `~/.dsh/xingxi/config.json`，
> 填 `记忆卡` 和 `日记` 两个路径（写法见「配置」）。没绑文件夹的会话，工具和 `/xingxi` 会读这两项。

### 第二步：让它把历史对话整理成档案（拾星）

**第一次绑好文件夹后先做这个**，之后档案由 AI 自己维护，不用再跑。

在星坊里点 **拾星**：

1. 插件会把这个会话的历史对话按天切开，一批只喂给 AI **1 天**
2. AI 交回「这一天的日记」+「该进记忆卡的条目」
3. 插件立刻落盘，然后自己派下一批，一直做到今天
4. 中途停了也没关系：进度记在文件里，再点一次（按钮会变成「接着拾」）从断点接着跑

跑完你会得到：

```
你选的文件夹\
  记忆卡.md              ← 按主题分章，拾星时按章追加
  日记\
    2026-09-06.md        ← 一天一个文件
    2026-09-07.md
    …
  原始对话\               ← 那天的原话，永久留着
    2026-09-06.txt
  .xingxi.json           ← 账本（整理到哪天、毫秒水位）
  .拾星\                  ← 当前任务的中间文件
    任务.json
    料\
```

**模型怎么选**：

1. 星坊里手选了 → 用你选的
2. 没选 → 跟**源会话自己用的模型**
3. 都没有 → 用主会话的默认模型

**拾星旁边还有两个按钮**：

| 按钮 | 什么时候用 | 做什么 |
|---|---|---|
| **补星** | 今天后面又聊了，但拾星说到今天就收手 | 只补今天 / 今天水位之后的新内容，不重做历史 |
| **停止** | 派错了、想先停下 | 掐掉当前这批，并让调度器不再派；已经落盘的日记和记忆卡不动 |

> 拾星会另开一个工作会话来干活，标题是 `拾星 · <源会话名> · <日期>`。
> 做完不会自动删；每批一个会话，跑的历史长了侧栏会多出不少，可以手动归档。
> **别删档案文件夹**——工作会话可以归档，档案删了就真没了。

### 第三步：压缩之后让它重读一遍

上下文被压缩、AI 开始「忘事」的时候，在会话里输入：

```
/xingxi
```

它会把这个会话文件夹里的**记忆卡整本 + 最近三天的日记**的文件路径递过去，
只给一句话，不往上下文里灌正文 —— 它自己用 `read` 分页读完。

## `/xingxi` 指令

| | |
|---|---|
| **作用** | 叫 AI 把记忆卡和最近三天日记读一遍 |
| **什么时候用** | 上下文刚被压缩、它开始答不上「我是谁」「我们之前说好的事」 |
| **怎么用** | 直接在会话里输入 `/xingxi`，不用带参数 |
| **它读什么** | **这个会话自己文件夹**里名字带「记忆卡」的 md + `日记\` 里最近 3 个文件 |
| **不会做什么** | 不塞正文进对话、不改任何文件 |
| **注意** | 会话得醒着；会话没醒着会报「这个会话没醒着」 |

如果这个会话还没绑文件夹，它会退回读「本机档案」的 `记忆卡` 和 `日记`。

## `xingxi_read` 工具（给 AI 用的）

上下文一压缩，AI 往往只记得「有这么回事」，记不清哪一天、原话怎么说的。
`xingxi_read` 让它能直接去档案里把那一小段翻出来，**而不是猜**。

**四种用法：**

### ① 什么都不给 → 先看索引

```
xingxi_read()
```

```
这个档案里有 101 个文件：

· 记忆卡（8.2 万字）
· 日记 50 天：2026-09-06 ~ 2026-11-04（一天一个文件）
· 原始对话 50 天：2026-09-06 ~ 2026-11-04（当天原话）

怎么查：给「关键词」全文搜（日记也会搜）；给「日期」看那一天；给「文件」看整篇。
```

**这就是「在外面就能查」**：不用打开每天的日记挨个翻，先看清有什么，再决定钻哪一天。

### ② 给关键词 → 全文搜（记忆卡、日记、原始对话都搜）

```
xingxi_read(关键词="结婚")
```

```
「结婚」在 2 个文件里出现 3 次：

【记忆卡】（2 处）
…
【日记/2026-09-10】（1 处）
…
```

每个文件都会扫，每份最多取 2 段，命中多的排前面；预算不够时会直说「还有 N 个文件也提到，想看就给『文件』参数点名」。

### ③ 给日期 → 直接看那一天

```
xingxi_read(日期="2026-09-10")
```

按文件名直接定位 `日记/2026-09-10.md`，给整篇。那天没有记录会告诉你日记覆盖的日期范围。

### ④ 给文件名 → 看整篇

```
xingxi_read(文件="我们的约定")
xingxi_read(文件="记忆卡")
```

按文件名匹配，名字里带这几个字就认。

**参数速查**

| 参数 | 说明 |
|---|---|
| `关键词` | 要搜的词，比如「卖号」「第一次」；中文两字以上效果最好 |
| `日期` | `YYYY-MM-DD`，也认 `11-03` 这种；查日记最准，因为日记按天分文件 |
| `文件` | 文件名或它的一部分 |
| `最多字` | 最多返回多少字，默认 4000；实际范围 600–20000，超了会被夹到边界 |

结果会尽量把「哪天、哪个文件、原文」一起带回来。
预算不够时会直说「还有 N 个文件也提到」，不会假装搜完了。

## `xingxi` 工具（给 AI 用的）

`xingxi_read` 是「查某一处」，`xingxi` 是「**通读整本记忆卡**」——
不分段、不翻页，一次读完。上下文刚被压缩完时用它最合适。

跟 `/xingxi` 指令的区别：指令是「叫它去读」（走 `read`，能分页）；工具是「直接把整本递过去」，
记忆卡特别大时可能被截断，一般优先用指令。

它取的是**当前会话**的档案；会话没绑文件夹时，退回读「本机档案」的 `记忆卡` / `日记`。
两边都没有时，它会直接说没找到，不会拿别的会话的档案来充数。

## 档案长什么样

拾星写出来的档案是普通 Markdown，你随时能自己改、自己加。

**记忆卡**：`##` 是一章，`###` 是一条。

```markdown
## 一、我是谁

### 身份

- 名字：星汐
- 在做什么：……

### 说话方式

- 短句，先说结论
```

- 每条 `###` 是一颗星；每个 `##` 章是一颗大一点的星
- 一章也可以是一整段自述，不拆成 `###`；这时整章算一颗星
- 拾星会按章追加，**不会重写整本**；只有在整章替换时才会先备份
- 星图**只读 `.md`**：`原始对话\` 里的 `.txt` 不会画进图里，但 `xingxi_read` 能搜到

**日记**：一天一个文件，文件名就是日期。

```markdown
# 2026-09-06

## 上午

- ……
```

- 一天一颗星，越新越亮
- 日记可以自己写，也可以让定时任务提醒 AI 写

**其余文件**：

- `原始对话\YYYY-MM-DD.txt` —— 那天的原话，拾星时按天写入，之后只追加不覆盖
- `.xingxi.json` —— 账本，记「已整理到哪天」和毫秒水位；手改会让进度错乱
- `.拾星\任务.json` —— 当前任务的进度、暂停状态、工作会话
- `记忆卡.md.bak-*` —— 整章替换前的自动备份，最多 20 份

## 拾星是怎么跑的

- **按天分批**：一批只给 **1 天**，上下文一直是小的，不会因为太长被压缩
- **点击就锁定范围**：点「拾星 / 补星」那一刻记下截止时间，之后的新消息不算这一批
- **交一批落一批**：一天一个日记文件 + 按章追加记忆卡，不攒到最后
- **插件自己派下一批**：进度写进任务文件，断了能从断点继续
- **到今天就收手**：进度追上今天自动停；今天后半截用「补星」
- **原始对话留底**：每天的原话永久存一份在 `原始对话\`；同一天再补时只追加新内容
- **自动暂停**：连续 3 次没进展会自己停下并写日志；点「接着拾」恢复
- **有备份**：整章替换记忆卡前自动存 `.bak-*`，最多 20 份
- **不删工作会话**：拾星开的工作会话会留着，你可以点进去看它做了什么

## 定时整理（可选）

星坊里的「定时」卡是**每个会话一份**的：到点自动整理这个会话的记忆卡和日记。

- 默认 **23:30**；点「几点」改时间
- 两个开关只能开一个：
  - **让会话自己拾星**：到点给这个会话发一句「今天的档案自己整理一下」，由它自己写。
    **这个会话得醒着**；DSH 关了或会话睡了就跳过，日志会写「会话没醒着，今天跳过」。
  - **让星汐拾星**：星汐另开一个工作会话，把今天的记忆卡和日记写掉。
- **DSH 得开着**：调度器在 DSH 进程里，关了就不会跑，也不会补跑。
- 到点没派成（没料 / 失败）会重试：没料隔 10 分钟再看，其他失败 5 分钟后重试，
  **23:59 之后今天不再试**。
- 只有时间或模式真的改了，今天才会允许重跑一次；只点一下、没改设置不会重复发。

> 旧版本的「写日记」卡已经换成这张「定时」卡；老字段（只卡 / 提醒日记 / 连日记）读的时候会自动迁移。

## 备份与恢复

- 整章替换记忆卡之前，插件会自动在记忆卡同目录存一份 `.bak-<时间戳>`，**最多留 20 份**。
- 星坊 →「备份」→「看备份」，列出最近的备份（面板里显示 12 条，更早的还在磁盘上）；
  点「恢复」用旧文件盖回来。
- 恢复前会先把当前文件再另存一份，恢复错了还能退。
- 只有发生过整章替换才会有备份，第一次拾星之前是空的。

## 配置

配置文件是 `~/.dsh/xingxi/config.json`。**没有设置界面**：
除了星坊里能改的（绑定、模型、定时、顺序），其余要手改这个文件；改之前先复制一份。

| 字段 | 类型 | 作用 |
|---|---|---|
| `绑定` | 对象 | 会话 id → 档案文件夹；星坊「选…」就是写这里，一般不用手改 |
| `记忆卡` | 字符串 | 「本机档案」的记忆卡 `.md` 文件路径 |
| `日记` | 字符串 | 「本机档案」的日记：文件夹（一天一个 .md）或单个 .md 文件 |
| `中心` | 字符串 | 「本机档案」在会话栏显示的名字；填某个会话标题时，会尝试并到那个会话（要求文件夹一致） |
| `模型` | 对象 | `{ "provider": "…", "model": "…" }`；星坊的模型下拉写这里。不填就跟源会话 / 默认 |
| `顺序` | 数组 | 会话栏的手动排序（会话 id 列表）；拖动时自动写 |
| `绑到会话` | 字符串 | 把「本机档案」并到指定会话 id；高级用法，一般不用 |
| `定时` | 对象 | `各` 里按会话 id 存 `{ 时, 分, 自己, 星汐 }`；`已发` 是去重记录，别手改 |

一个例子（路径是 Windows 写法；JSON 里反斜杠要写两个，并且**不能有尾逗号**）：

```json
{
  "绑定": {
    "session-xxxxxxxx": "D:\\档案\\某某"
  },
  "记忆卡": "D:\\档案\\本机\\记忆卡.md",
  "日记": "D:\\档案\\本机\\日记",
  "中心": "本机档案",
  "模型": { "provider": "<provider-id>", "model": "<model-id>" },
  "顺序": ["session-xxxxxxxx"],
  "定时": {
    "各": {
      "session-xxxxxxxx": { "时": 23, "分": 30, "自己": false, "星汐": true }
    }
  }
}
```

**本机档案怎么配**：

1. 建一个文件夹，里面放 `记忆卡.md` 和 `日记\`（日记也可以是一个大文件）
2. 在 `config.json` 里填 `记忆卡`、`日记`，可选 `中心`
3. 刷新面板或重开 DSH；会话栏会出现「本机档案」，或者并到同目录的那个会话
4. 本机档案**不用绑文件夹**，但**不能拿它当拾星源 / 定时源**；
   想整理就把它并到一个真实会话（`中心` 或 `绑到会话`），或者在那个会话里绑同一个文件夹

**改完没生效，按顺序查**：

1. JSON 语法：尾逗号、单反斜杠、中文引号都会让整个文件读不出来
2. 路径存在，且 `记忆卡` 是 `.md` 文件
3. 刷新星汐面板（或重开 DSH）
4. `~/.dsh/xingxi/pick.log` 里有没有「写不进去 / 读不了」

## 常见问题

**侧栏没有「星汐」**

- 装完没重开 DSH；重开一次
- 装到了别的 profile：看一下 `dsh plugin list` 里有没有 `dsh-xingxi`
- DSH 版本低于 0.2.1-rc.2：升级 DSH

**面板是空的 / 没有星**

- 这个会话还没绑文件夹：星坊 → 现在这个会话 → 选…
- 文件夹里没有任何 `.md`（星图只读 `.md`，根目录和一层子目录都算），也没有 `日记\`
- 只列当前工作区的会话：切到对应工作区
- 文件夹里只有 `.txt`：星图不画，但 `xingxi_read` 能搜

**点了拾星，说「没有可整理的日子」**

- 已经整理到今天了；今天后面的新内容用「补星」
- 会话里没有真人发言（注入的上下文会被滤掉）
- 看 `~/.dsh/xingxi/pick.log` 的最后几行

**拾星一直开新会话 / 停不下来**

- 升级到 0.3.0+：进度到今天就收手，后面的归「补星」
- 点「停止」；再点「拾星」会从断点继续
- 连续 3 次没进展会自动暂停，日志写原因

**定时到点没动**

- 星坊里的开关没开
- DSH 没开：调度器不在，关机就跳过
- 「让会话自己拾星」要求那个会话醒着；睡了会跳过
- 过了 23:59 今天不再试；空料要等 10 分钟才会重试
- 看 `pick.log`

**标题变成「拾星 · 拾星 · …」**

- 0.3.2 已修：现在取源会话名，并先剥前缀。升级即可。

**记忆卡一直没有第二章**

- 旧版本的 bug（整章替换没有回退）。升级到最新版即可。

**有没有浅色主题**

- 没有。深色是写死的，星点的光晕依赖深色底（canvas 的 `screen` / `lighter`）；见 [issue #3](https://github.com/Yuuyuko-uu/dsh-xingxi/issues/3)。

**工作会话太多**

- 每批新开一个，做完不自动删；手动归档 / 删除工作会话即可。**别删档案文件夹**。

**备份在哪**

- 记忆卡同目录的 `.bak-*`；星坊 →「备份」也能看、能恢复。

**改了 config.json 没生效**

- 见「配置」最后的检查顺序。

## 它怎么工作

```
DSH 会话日志 ──按天切──▶ .拾星\料\*.txt ──整段内联进提示词──▶ 工作会话
                                                              │ 交回「记忆卡块 / 日记块」
                                                              ▼
                                     写回 记忆卡.md、日记\、原始对话\、.xingxi.json
```

- **宿主** `index.js`：注册 `/dsh-xingxi/*` 的本地 HTTP 路由、`xingxi` / `xingxi_read` 工具、
  `/xingxi` 指令，跑定时调度和拾星派批。
- **客户端** `client.js`：注册 Web 侧栏面板，四个页签；星图用 canvas 画。
- **星和线**：记忆卡 `###` 一条一颗、`##` 一章一颗；日记一天一颗。
  线 = 同章相邻 + 二字组相似 + 共享罕见词；越新越亮按内容日期算。
- **读写范围**：读绑定文件夹里的档案，拾星时还会读当前工作区的会话记录；
  写只发生在绑定文件夹里 —— `记忆卡.md`、`日记\`、`原始对话\`、`.xingxi.json`、`.拾星\`。
- **不联网**：星汐自己不发网络请求；拾星时是 DSH 在跟模型服务通信。

## 和「鱼的记忆」怎么分工

- **鱼的记忆**：管会淡忘的记忆、权重、每轮注入。
- **星汐**：把已经整理好的档案摊开给你看，并把历史对话整理成档案。
- 两个都装不冲突；星汐不替代鱼的记忆，也不做遗忘 / 衰减。

搭配使用效果更好：[dsh-fish-memory](https://github.com/Yuuyuko-uu/dsh-fish-memory)

## 已知边界

- **只有深色**：没有浅色主题；星点的光晕依赖深色底
- **相似度是「两字一组」的重叠率**：中文够用，但不懂语义
- **星数到几千颗会开始卡**
- **只理解两种结构**：记忆卡（`##` / `###` 分节）和日记（一天一个 `.md`）；
  其他 `.md` 会被当成一颗整体星
- **会话列表跟 DSH 侧栏对齐**：只列当前工作区、没归档、有档案的会话
- **拾星靠模型按格式交块**：模型不听话时会漏写 / 写错章；看 `pick.log` 和备份
- **一批只做 1 天**：历史很长时会开很多工作会话
- **定时依赖 DSH 开着**：关了不会补跑
- **本机档案只能看和查**：不能拿它当拾星源，也不能定时
